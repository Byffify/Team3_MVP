# คู่มือทดลองกับทีมเต็นท์ 3 คน

## เตรียม

ใช้เครื่องเดียว Chrome หรือ Edge โปรไฟล์ปกติ URL http://127.0.0.1:5173/ เตรียมรูปสมมติ JPG/PNG หรือ PDF และผู้ทดลอง 3 คน ใช้รถสมมติคนละคัน ไม่ใช้ข้อมูลส่วนตัวจริง

รถตัวอย่างสำหรับโจทย์: Toyota Hilux Revo ปี 2020, ทะเบียน ทดลอง 101, ผู้ขายสมมติ A, ไม่ทราบเลขตัวถังและเลขเครื่อง ดูเอกสารสำเนาแล้วแต่ยังต้องขอต้นฉบับ ยังไม่ได้ทดลองขับ ผู้ทดลองคนที่สองและสามใช้ทะเบียน ทดลอง 102 และ ทดลอง 103

อธิบายเพียงว่าแอปใช้บันทึกการตรวจ ไม่ยืนยันประวัติหรือความปลอดภัย ให้เริ่มโดยไม่สอนตำแหน่งปุ่ม ผู้สังเกตไม่กรอกแทน บันทึกทุกครั้งที่ต้องช่วย

## โจทย์และการจับเวลา

1. เริ่มจับเวลาเมื่อกด “เพิ่มรถ”
2. บันทึกข้อมูลรถจากโจทย์ กรอกเฉพาะข้อมูลที่มี
3. ตั้ง “ตรวจเอกสารทะเบียนและข้อมูลผู้ขาย” เป็นต้องตรวจเพิ่ม พร้อมหมายเหตุ “ขอต้นฉบับ” และแหล่งข้อมูล “ผู้ขายสมมติ A”; แนบไฟล์สมมติ
4. ตั้ง “เปรียบเทียบทะเบียนและข้อมูลรถกับเอกสาร” เป็นตรวจแล้ว ที่เหลือยังไม่ได้ตรวจ
5. ดูสรุปผลตรวจ แล้วสร้างรายงาน หยุดเวลาเมื่อเห็นรายงาน
6. ถาม “รถคันนี้ยังมีเรื่องใดที่ต้องตรวจต่อ?” ก่อนชี้ตำแหน่งคำตอบ
7. ทดลองบันทึก PDF จากเบราว์เซอร์ ตรวจ A4 หนึ่งหน้า
8. ปิดและเปิดเบราว์เซอร์อีกครั้ง เปิดรถคันเดิม ตรวจข้อมูลรถ สถานะ หมายเหตุ แหล่งข้อมูลและชื่อไฟล์; ไฟล์จริงต้องแนบใหม่เป็นพฤติกรรมที่ตั้งใจไว้

## คำถามหลังทดลอง

- ต้องการใช้กับรถจริงอีกหรือไม่? เพราะอะไรอย่างน้อยหนึ่งข้อ?
- ขั้นตอนไหนที่สับสนหรือช้าที่สุด?
- เข้าใจหรือไม่ว่า “ตรวจแล้ว” ไม่ใช่การรับรองว่ารถปลอดภัย?
- การใช้เครื่องร่วมกันและต้องแนบไฟล์ใหม่รบกวนการทำงานอย่างไร?

บันทึกคำตอบตามจริงใน trial-results.csv ใช้ P01–P03 แทนชื่อผู้ทดลอง

## เกณฑ์

- 3/3 คนบันทึกรถได้โดยผู้พัฒนาไม่กรอกแทน
- อย่างน้อย 2/3 คนสร้างรายงานภายใน 300 วินาที
- อย่างน้อย 2/3 คนบอกได้ว่าขอต้นฉบับเอกสารและรายการที่ยังไม่ได้ตรวจต้องติดตามต่อ
- เปิดเบราว์เซอร์ใหม่แล้วข้อมูลรถ/สถานะยังอยู่
- ทั้งสามคนตอบเรื่องการใช้กับรถจริงพร้อมเหตุผล คำตอบ “ไม่ใช้” ก็เป็นผลทดลองที่มีประโยชน์ ไม่ใช่เหตุให้ลบผลนั้น

สรุปเป็น ผ่าน/ไม่ผ่านรายเกณฑ์ ระบุจุดติดขัดและเลือกแก้สิ่งที่ขัดขวาง flow ก่อน ห้ามอ้างว่าผลจากสามคนพิสูจน์การยอมรับของตลาด
