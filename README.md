# ก่อนซื้อ — MVP บันทึกตรวจรถ

เว็บแอปภาษาไทยสำหรับทีมเต็นท์รถมือสอง บันทึกข้อมูลรถ เช็กลิสต์ 8 รายการ หลักฐาน และสร้างรายงาน A4 หนึ่งหน้า ไม่มี backend บัญชีผู้ใช้ หรือการตรวจประวัติอัตโนมัติ

## เปิดใช้งานบนเครื่องนี้

ต้องมี Node.js 24 ขึ้นไป จากโฟลเดอร์ `D:\Startup_MVP`:

```powershell
npm.cmd run dev
```

เปิด **http://127.0.0.1:5173/** ใน Chrome หรือ Edge ใช้ URL นี้ เบราว์เซอร์นี้ และโปรไฟล์เดิมทุกครั้ง หากใช้ `localhost` แทน `127.0.0.1` จะเป็นข้อมูลคนละชุด

แพ็กเกจในเครื่องนี้พร้อมใช้งานแล้ว การติดตั้งบนเครื่องอื่นที่มีอินเทอร์เน็ตใช้ `npm ci` (บน PowerShell ใช้ `npm.cmd ci` หาก `npm.ps1` ถูกบล็อก)

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

หยุด dev server ก่อนใช้ preview เพราะทั้งสองใช้พอร์ต 5173 เพื่อรักษา origin เดิม อย่าเปิด `dist/index.html` ผ่าน `file://` โดยตรง

## วิธีทดลอง

1. กดเพิ่มรถ หรือโหลดรถตัวอย่าง 2 คันจากหน้าว่าง ตัวอย่างเป็นข้อมูลสมมติทั้งหมด
2. กรอกรุ่นและวันที่ตรวจ ช่องอื่นเว้นว่างได้ กดบันทึกข้อมูลรถ
3. เปลี่ยนแต่ละรายการเป็น ยังไม่ได้ตรวจ / ต้องตรวจเพิ่ม / ตรวจแล้ว
4. กรอกหมายเหตุและแหล่งข้อมูล ก่อนแนบ JPG, PNG หรือ PDF ไม่เกิน 10 MB หนึ่งไฟล์ต่อรายการ
5. เปิดสรุปผลตรวจ เพื่อเห็นข้อมูลว่างและรายการที่ต้องติดตาม
6. กดสร้างรายงาน แล้วพิมพ์ / บันทึก PDF เลือก A4 แนวตั้ง, Scale 100%, ปิด Headers and footers

## ข้อจำกัดที่ต้องเข้าใจ

- ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์เดิม ไม่มีการซิงก์หรือสำรองข้อมูลส่วนกลาง การล้าง site data จะลบข้อมูลนี้
- รุ่นนี้ใช้เครื่องทดลองร่วมกัน ทีมไม่ได้เปิดข้อมูลชุดเดียวกันข้ามเครื่อง
- เก็บชื่อไฟล์ถาวร แต่ไม่เก็บไฟล์จริงไว้หลัง reload หรือปิดแอป ต้องแนบใหม่เพื่อเปิดดูไฟล์เดิม
- การเปลี่ยนสถานะ หมายเหตุ และแหล่งข้อมูลบันทึกทันที ข้อมูลรถบันทึกเมื่อกดปุ่ม ระบบแจ้งเมื่อเขียนไม่ได้
- ไม่ใช้ private/incognito mode สำหรับการทดลอง persistence
- รายงานแสดงทะเบียน เลขตัวถัง และเลขเครื่องเต็ม ไม่ย่อเลขระบุตัวรถ รายการที่ต้องติดตามและยังไม่ได้ตรวจแสดงก่อนรายการตรวจแล้ว
- รายงานไม่ฝังรูปหรือ PDF; หมายเหตุย่อที่ 100 ตัวอักษร พร้อมเครื่องหมาย `(ย่อ)` ข้อความเต็มอยู่ในแอป แหล่งข้อมูลและชื่อไฟล์อาจย่อด้วย ควรเริ่มหมายเหตุด้วยสิ่งที่ต้องติดตาม
- รายงานทั่วไปใช้ตัวอักษรตาราง 8.5pt; กรณีข้อความมากหรือเลขระบุตัวรถยาวใช้รูปแบบกระชับ 7.5pt เพื่อรักษา A4 หนึ่งหน้า
- ข้อมูลตัวอย่างที่โหลดใหม่แยกรายการที่รอเอกสารจริงเป็น “ต้องตรวจเพิ่ม” ข้อมูลที่เคยบันทึกไว้ไม่เปลี่ยนสถานะอัตโนมัติ
- “ตรวจแล้ว” คือสถานะบันทึกของทีม ไม่ได้หมายความว่ารถผ่าน ปลอดภัย หรือไม่มีประวัติเสียหาย
- ถ้าข้อมูลเสียหรือเป็น schema อื่น ระบบหยุดเขียนเพื่อรักษาข้อมูลเดิม รุ่นนี้ไม่มีปุ่มล้างข้อมูลหรือ migration อัตโนมัติ

## โครงสร้าง

- `src/model.ts`: data model, เช็กลิสต์, validation, อ่าน/เขียน storage และรถตัวอย่าง
- `src/App.tsx`: รายการรถ ฟอร์ม เช็กลิสต์ สรุป รายงาน และดูหลักฐาน
- `src/styles.css`: responsive layout และ CSS สำหรับพิมพ์
- `src/model.test.ts`: unit tests ใช้ test runner ที่มากับ Node
- `tests/browser.test.ts`: integration tests แบบ headless ผ่าน Chromium CDP ใช้โปรไฟล์แยกใน `.cache` ไม่เปิดข้อมูลเบราว์เซอร์ของผู้ใช้
- `docs/trial-guide.md`, `docs/trial-results.csv`: คู่มือและแบบบันทึกการทดลองจริง

## การทดสอบเบราว์เซอร์

เปิด dev server ก่อน แล้วรันในอีก terminal:

```powershell
npm.cmd run test:e2e
```

ค้นหา Edge/Chrome ที่ติดตั้งไว้โดยอัตโนมัติ หรือกำหนด `$env:BROWSER_EXECUTABLE` เป็น path ของเบราว์เซอร์ ทดสอบด้วยข้อมูลสมมติในโปรไฟล์ชั่วคราวที่แยกจากโปรไฟล์จริง สร้างภาพ QA และ PDF ตัวอย่างเมื่อผ่านถึงขั้นตอนนั้น อ่านผลจริงใน `docs/verification.md` ก่อนถือว่าการทดสอบทั้งหมดผ่าน
